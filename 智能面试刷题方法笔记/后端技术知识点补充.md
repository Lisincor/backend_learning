# QueryWrapper 的核心作用

`QueryWrapper` 是 MyBatis Plus 提供的**条件构造器**，它的核心作用是**动态构建 SQL 查询条件**，无需手动编写 SQL 语句。

## 1. 工作原理

java

```
// 当调用 questionService.page(page, wrapper) 时
QueryWrapper<Question> wrapper = new QueryWrapper<>();
wrapper.eq("difficulty", 3);
wrapper.like("title", "Java");

// MyBatis Plus 会自动生成类似这样的 SQL：
// SELECT * FROM question 
// WHERE difficulty = 3 AND title LIKE '%Java%'
// LIMIT 0, 10
```



## 2. QueryWrapper 的主要功能

### 2.1 **条件筛选**

java

```
QueryWrapper<Question> wrapper = new QueryWrapper<>();

// 等值查询
wrapper.eq("difficulty", 3);              // difficulty = 3
wrapper.eq("status", "PUBLISHED");        // status = 'PUBLISHED'

// 范围查询
wrapper.gt("score", 60);                  // score > 60
wrapper.ge("create_time", "2024-01-01");  // create_time >= '2024-01-01'
wrapper.lt("score", 100);                 // score < 100
wrapper.le("update_time", "2024-12-31");  // update_time <= '2024-12-31'

// 模糊查询
wrapper.like("title", "Java");            // title LIKE '%Java%'
wrapper.likeLeft("content", "Spring");    // content LIKE '%Spring'
wrapper.likeRight("author", "张");        // author LIKE '张%'

// 区间查询
wrapper.between("score", 60, 90);         // score BETWEEN 60 AND 90

// IN 查询
wrapper.in("category_id", 1, 2, 3);       // category_id IN (1,2,3)
```



### 2.2 **多条件组合**

java

```
QueryWrapper<Question> wrapper = new QueryWrapper<>();

// AND 连接（默认）
wrapper.eq("difficulty", 3)
       .like("title", "Java")
       .ge("score", 80);
// WHERE difficulty = 3 AND title LIKE '%Java%' AND score >= 80

// OR 连接
wrapper.eq("difficulty", 1)
       .or()
       .eq("difficulty", 2);
// WHERE difficulty = 1 OR difficulty = 2

// 嵌套条件
wrapper.and(w -> w.eq("type", "SINGLE").eq("status", 1))
       .or(w -> w.eq("type", "MULTIPLE").eq("status", 2));
// WHERE (type = 'SINGLE' AND status = 1) OR (type = 'MULTIPLE' AND status = 2)
```



### 2.3 **字段排序**

java

```
QueryWrapper<Question> wrapper = new QueryWrapper<>();

// 单字段排序
wrapper.orderByDesc("create_time");  // ORDER BY create_time DESC
wrapper.orderByAsc("score");         // ORDER BY score ASC

// 多字段排序
wrapper.orderByDesc("difficulty")
       .orderByAsc("create_time");
// ORDER BY difficulty DESC, create_time ASC
```



### 2.4 **字段选择**

java

```
QueryWrapper<Question> wrapper = new QueryWrapper<>();

// 只查询指定字段
wrapper.select("id", "title", "difficulty", "score");
// SELECT id, title, difficulty, score FROM question ...

// 排除某些字段
wrapper.select(Question.class, info -> 
    !info.getColumn().equals("content") && 
    !info.getColumn().equals("answer")
);
```



## 3. 在实际业务中的应用

### 3.1 **动态条件构建**

java

```
public QueryWrapper<Question> getQueryWrapper(QuestionQueryRequest request) {
    QueryWrapper<Question> wrapper = new QueryWrapper<>();
    
    // 只有参数不为空时才添加条件
    if (StringUtils.hasText(request.getTitle())) {
        wrapper.like("title", request.getTitle());
    }
    
    if (request.getDifficulty() != null) {
        wrapper.eq("difficulty", request.getDifficulty());
    }
    
    if (request.getCategoryId() != null) {
        wrapper.eq("category_id", request.getCategoryId());
    }
    
    if (request.getStartScore() != null && request.getEndScore() != null) {
        wrapper.between("score", request.getStartScore(), request.getEndScore());
    }
    
    // 时间范围查询
    if (request.getStartTime() != null) {
        wrapper.ge("create_time", request.getStartTime());
    }
    if (request.getEndTime() != null) {
        wrapper.le("create_time", request.getEndTime());
    }
    
    // 排序
    if (StringUtils.hasText(request.getOrderBy())) {
        if ("asc".equalsIgnoreCase(request.getOrderDirection())) {
            wrapper.orderByAsc(request.getOrderBy());
        } else {
            wrapper.orderByDesc(request.getOrderBy());
        }
    } else {
        wrapper.orderByDesc("create_time"); // 默认按创建时间倒序
    }
    
    return wrapper;
}
```



### 3.2 **复杂查询场景**

java

```
// 多表关联查询
QueryWrapper<Question> wrapper = new QueryWrapper<>();
wrapper.eq("q.status", 1)  // q 是表别名
       .inSql("q.category_id", "SELECT id FROM category WHERE level = 1")
       .ge("q.score", 60)
       .apply("DATE(q.create_time) = {0}", LocalDate.now());

// 使用 Sql 函数
wrapper.apply("YEAR(create_time) = {0}", 2024)
       .apply("MONTH(create_time) = {0}", 12);

// 存在性查询
wrapper.exists("SELECT 1 FROM answer WHERE answer.question_id = id AND answer.is_correct = 1");
```



## 4. QueryWrapper 的优势

### 4.1 **安全性**

java

```
// ❌ 不安全的 SQL 拼接
String sql = "SELECT * FROM question WHERE title LIKE '%" + title + "%'";
// 存在 SQL 注入风险

// ✅ 使用 QueryWrapper 自动参数化
wrapper.like("title", title);
// 自动使用 PreparedStatement，防止 SQL 注入
```



### 4.2 **代码简洁性**

java

```
// 传统方式：需要手动写大量 if 判断拼接 SQL
StringBuilder sql = new StringBuilder("SELECT * FROM question WHERE 1=1");
if (title != null) {
    sql.append(" AND title LIKE '%").append(title).append("%'");
}
// ... 更多条件

// QueryWrapper 方式：链式调用，代码更清晰
wrapper.like(StringUtils.hasText(title), "title", title)
       .eq(difficulty != null, "difficulty", difficulty)
       .ge(startScore != null, "score", startScore);
```



### 4.3 **可维护性**

java

```
// 将查询逻辑封装在方法中，便于复用和测试
public QueryWrapper<Question> buildSearchWrapper(QuestionSearchDTO searchDTO) {
    QueryWrapper<Question> wrapper = new QueryWrapper<>();
    
    // 复杂的业务逻辑都集中在这里
    if (searchDTO.isAdvancedSearch()) {
        // 高级搜索逻辑
        wrapper.and(w -> w.like("title", searchDTO.getKeyword())
                        .or()
                        .like("content", searchDTO.getKeyword()));
    } else {
        // 简单搜索逻辑
        wrapper.like("title", searchDTO.getKeyword());
    }
    
    return wrapper;
}
```

java

wrapper.select("id", "title", "difficulty")
       .eq("status", 1)
       .like("title", "Java")
       .ge("score", 60)
       .orderByDesc("create_time")
       .last("LIMIT 10");

## 总结

`QueryWrapper` 在查询中的作用可以概括为：

1. **条件构造**：通过链式调用构建 WHERE 条件
2. **动态查询**：根据业务需求动态添加/移除查询条件
3. **SQL 优化**：自动处理参数化查询，防止 SQL 注入
4. **代码简化**：减少重复的 SQL 拼接代码
5. **类型安全**：通过泛型确保查询的实体类型正确
6. **灵活扩展**：支持复杂的 SQL 逻辑（子查询、函数、多表关联等）

它是 MyBatis Plus 实现**无 SQL 或少 SQL 开发**的核心工具，大大提升了开发效率和代码质量。

# LambdaQueryWrapper以及一些使用原理

1.select(QuestionBankQuestion::getQuestionId) // 由QuestionId映射到数据库字段

```java
public Page<Question> listQuestionByPage( QuestionQueryRequest questionQueryRequest) {
        long current = questionQueryRequest.getCurrent();
        long size = questionQueryRequest.getPageSize();


        QueryWrapper<Question> queryWrapper = this.getQueryWrapper(questionQueryRequest);


        //根据题库查询题目列表
        Long questionBankId = questionQueryRequest.getQuestionBankId(); //从DTO类中获取题库id
        if (questionBankId != null) {
            LambdaQueryWrapper<QuestionBankQuestion> lambdaQueryWrapper = Wrappers.lambdaQuery(QuestionBankQuestion.class)
                    .select(QuestionBankQuestion::getQuestionId) // 由QuestionId映射到数据库
                    .eq(QuestionBankQuestion::getQuestionBankId, questionBankId);

            //执行查询，返回的每个对象只有questionId有值，其他都为null
            List<QuestionBankQuestion> list = questionBankQuestionService.list(lambdaQueryWrapper);
            if(CollectionUtils.isEmpty(list)){
                //将list中的questionId提取出来，组成一个新的list
                List<Long> ids = list.stream().map(QuestionBankQuestion::getQuestionId).collect(Collectors.toList());
                //查询题库内的题目
                queryWrapper.in("id", ids);
            }
        }


        // 查询数据库
        Page<Question> questionPage = this.page(new Page<>(current, size), queryWrapper);
        return questionPage;
    }
```

# SpringBoot 的 application.yml文件补充

完全是。Spring Boot **不是通过识别 `application` 文件的后缀**来决定加载哪个配置文件的，而是通过 **命名约定** 和 **激活的 profile** 来决定的。

## 配置文件的加载机制

### 1. **命名约定**

Spring Boot 会按照以下命名规则加载配置文件：

text

```
application-{profile}.{后缀}
```



- `{profile}` 是激活的环境名称（如 local、dev、prod）
- 后缀可以是 `.properties` 或 `.yml`

### 2. **如何决定加载哪个 profile**

有两种方式指定激活的 profile：

#### 方式一：在 `application.yml` 中配置

yaml

```
spring:
  profiles:
    active: local  # 激活 local profile
```



#### 方式二：启动时指定

bash

```
# 命令行参数
java -jar app.jar --spring.profiles.active=local

# 环境变量
export SPRING_PROFILES_ACTIVE=local
java -jar app.jar

# JVM 参数
java -jar -Dspring.profiles.active=local app.jar
```



### 3. **配置文件加载顺序**

当激活 `local` profile 时，Spring Boot 会加载：

1. `application.yml` （基础配置，总是加载）
2. `application-local.yml` （profile 特定配置）
3. 同名配置会**覆盖**基础配置

## 示例说明

假设你有以下文件：

text

```
application.yml          # 基础配置
application-local.yml    # local 环境配置
application-dev.yml      # dev 环境配置
```



### 情况1：`spring.profiles.active=local`

yaml

```
# application.yml
server:
  port: 8080
  
# application-local.yml
server:
  port: 8123  # 覆盖基础配置，最终端口为 8123
```



### 情况2：`spring.profiles.active=dev`

yaml

```
# application.yml
server:
  port: 8080
  
# application-dev.yml
server:
  port: 9090  # 覆盖基础配置，最终端口为 9090
```



## 多个 profile 同时激活

yaml

```
spring:
  profiles:
    active: local,dev  # 激活多个，后面覆盖前面
```



## 总结

- Spring Boot **不是通过后缀识别**，而是通过 **profile 名称匹配**
- 必须先在某个地方指定 `spring.profiles.active` 的值
- 然后 Spring Boot 根据这个值去加载对应的 `application-{profile}.yml`
- 基础配置文件 `application.yml` 始终会被加载

在你的配置中：

yaml

```
spring:
  profiles:
    active: local  # 这里指定激活 local
```

# Mybatis-plus的使用疑点

为什么2注入注解能直接找到实现类

虽然 `blogService` 声明的是接口类型 `IBlogService`，但Spring在运行时实际上注入的是该接口的**实现类对象**。

### 1. **Spring如何找到实现类**

java

```
// 接口
public interface IBlogService extends IService<Blog> {
    Result saveBlog(Blog blog);
}

// 实现类 - 关键注解
@Service  // 或 @Component
public class BlogServiceImpl implements IBlogService {
    
    @Override
    public Result saveBlog(Blog blog) {
        // 具体实现逻辑
        return Result.ok();
    }
}
```



Spring在容器启动时会：

1. 扫描所有带有 `@Service`、`@Component` 等注解的类
2. 将 `BlogServiceImpl` 注册为一个Bean
3. 发现它实现了 `IBlogService` 接口
4. 建立接口和实现类的映射关系
